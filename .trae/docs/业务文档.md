## 1. 项目概述

| 项目 | 说明 |
|------|------|
| **名称** | AI Video Studio |
| **定位** | AI 短视频创作平台。输入故事文本，AI 自动完成角色提取、分镜、图像/视频/语音/BGM 生成，最终通过 FFmpeg 合成成片 |
| **技术栈** | React 19 + TypeScript 6、Vite 8、React Router DOM 7、Dexie（IndexedDB ORM，v12，15 张表）、FFmpeg WASM、Axios、i18next 26、Lucide React、AES-GCM 256 加密 |
| **架构模式** | 六边形架构（Ports & Adapters），依赖方向 `ui -> domain <- adapters`，`domain` 永远不依赖外层 |
| **AI 平台** | 8 个：MiniMax（海螺）/ Volcengine（即梦·火山）/ Kling（可灵）/ Wan（万相）/ Hunyuan（混元）/ Zhipu（智谱）/ Vidu |
| **运行模式** | Local-First 纯前端运行，无后端依赖 |
| **开源协议** | Apache 2.0 |

### 技术架构分层

```
src/domain/   领域核心：纯业务逻辑，零框架依赖
src/adapters/ 出站适配器：实现 Port，对接外部 API/存储/浏览器
src/ui/       表现层：React 组件/Hook/Page
```

**铁律：依赖方向只能 `ui -> domain <- adapters`，`domain` 永远不依赖外层。**

## 4. 核心业务流程

AI Video Studio 的核心业务流程为端到端的短视频自动化创作链路：

```
故事文本
  │
  ▼
AI 分镜（Shot Splitting）
  │
  ▼
角色提取 / 场景绑定（Character Extraction / Scene Binding）
  │
  ▼
生成图像 / 旁白 / BGM / 字幕（Multi-modal Generation）
  │
  ▼
生成视频（多平台路由 Video Generation）
  │
  ▼
时间线编辑（Timeline Editing）
  │
  ▼
FFmpeg 后期制作（Post-production）
  │
  ▼
最终导出（Final Export）
```

### 流程说明

1. **故事输入**：用户在 StoryWorkbench 输入故事文本
2. **AI 分镜**：系统调用 `storyBreakdownPort.breakdownStory()` 进行 AI 分镜，不可用时降级为本地分镜（按句号/感叹号/问号/换行符切分，最多 8 段）
3. **角色与场景**：AI 提取角色并绑定到对应场景
4. **多模态生成**：批量生成角色/场景图像、旁白语音、BGM 音乐、字幕
5. **视频生成**：通过 PlatformRouter 路由到激活平台的视频适配器，支持 T2V/I2V/FL2V/S2V
6. **时间线编辑**：4 轨道可视化编辑（视频/旁白/BGM/字幕）
7. **后期制作**：FFmpeg WASM 合并视频、混音、烧录字幕、淡入淡出转场
8. **导出成片**：生成最终视频，可预览与下载

## 5. Pipeline 九阶段编排

`PipelineService` 负责全流程编排，共 9 个阶段，每个阶段对应一个进度区间：

```
splitting -> generating_images -> generating_audio -> generating_bgm
         -> generating_videos -> post_processing -> generating_srt
         -> burning_subtitles -> complete
```

### 阶段详情

| 阶段 | 进度区间 | 说明 |
|------|----------|------|
| **1. splitting** | 2% - 5% | 加载片段 / AI 分镜。优先 `storyBreakdownPort.breakdownStory()` AI 分镜，降级为本地分镜（按句号/感叹号/问号/换行符切分，最多 8 段） |
| **2. generating_images** | 10% - 20% | 生成角色/背景图像。优先 `PromptContextBuilder.build()` 构建结构化提示词，降级为 `seg.content.slice(0,500)`。追加 videoStyle 后缀。16:9 比例 |
| **3. generating_audio** | 25% - 40% | 生成旁白音频。遍历片段角色，使用角色 voiceId 调用 `synthesizeSpeechSync`。持久化到 OPFS，持久化失败回退原始 URL |
| **4. generating_bgm** | 45% - 50% | 生成 BGM。调用 `BGMRecommendationService.recommend()` 推荐风格，再调用 `MusicService.generateBGM()`。默认纯音乐 |
| **5. generating_videos** | 55% - 80% | 生成视频。两步走 + PromisePool（并发=3）：(a) 构建视频提示词，(b) 提交视频任务。降级轮询（5 秒间隔，最大 120 次 = 10 分钟） |
| **6. post_processing** | 82% - 90% | 后期制作。`assembleFinalVideo()`：下载视频 -> 音频混音（旁白+BGM）-> `mergeVideoAudio` -> 片段间淡入淡出转场 -> 烧录字幕 -> 提取缩略图 |
| **7. generating_srt** | 91% - 92% | 字幕生成（包含在 `assembleFinalVideo` 中） |
| **8. burning_subtitles** | 93% - 95% | 字幕烧录（包含在 `assembleFinalVideo` 中） |
| **9. complete** | 100% | 设置 `finalVideoUrl`，关联 `finalCutId` |

### 关键设计点

- **并发控制**：视频生成阶段使用 PromisePool，并发数为 3
- **降级轮询**：视频任务采用 5 秒间隔轮询，最大 120 次（10 分钟超时）
- **持久化降级**：音频持久化失败时回退原始 URL，保证 UI 不中断
- **OPFS 优先**：大资源优先落 OPFS，避免 data:URI 膨胀与外部 URL 过期

## 6. 视频生成模式

AI Video Studio 支持 4 种视频生成模式，不同平台支持的能力有所差异：

| 模式 | 全称 | 说明 |

| **T2V** | Text to Video | 文本生成视频 |
| **I2V** | Image to Video | 图像生成视频 |

## 7. AI Agent 与工具体系

`AgentService` 采用 ReAct（Reasoning + Acting）工具循环架构，最大迭代次数为 10 次。`ToolRegistry` 注册了 13 个工具，覆盖创作全链路：

### 工具清单

| 序号 | 工具名 | 功能 |
|------|--------|------|
| 1 | `create_character` | 创建角色 |
| 2 | `create_background` | 创建背景 |
| 3 | `create_story` | 创建故事 |
| 4 | `split_story` | 分镜 |
| 5 | `generate_character_image` | 生成角色图像 |
| 6 | `generate_background_image` | 生成背景图像 |
| 7 | `generate_video` | 生成视频 |
| 8 | `synthesize_voice` | 合成语音 |
| 9 | `generate_bgm` | 生成 BGM |
| 10 | `recommend_bgm` | 推荐 BGM |
| 11 | `suggest_shots` | 分镜建议 |
| 12 | `assemble_video` | 合成视频 |
| 13 | `get_story_status` | 获取故事状态 |

### ReAct 循环机制

```
用户指令
  │
  ▼
┌─────────────────────────────┐
│  Reasoning（推理：选择工具）  │ ◄── 最大 10 次迭代
│         ↓                    │
│  Acting（执行：调用工具）     │
│         ↓                    │
│  Observation（观察：获取结果）│
└─────────┬───────────────────┘
          │
          ▼
      最终回复
```

Agent 可在 Dashboard 内嵌的 `AgentChatPanel` 中以对话方式辅助创作，提供自动剪辑、摄影建议等能力。

## 9. 数据存储架构

AI Video Studio 采用 **Local-First 双层存储架构**，无后端依赖：

```
┌─────────────────────────────────────────────────┐
│                  应用层                          │
└────────┬────────────────────────────────────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌────────┐ ┌──────────────┐
│IndexedDB│ │  FilesLocal   │
│(Dexie)  │ │  (FILES_DIR)  │
│元数据   │ │  二进制 Blob   │ ← 优先
│15 张表  │ └──────┬───────┘
└────────┘        │ 不可用时降级
                   ▼
            ┌──────────────┐
            │     OPFS      │
            │ Origin Private │
            │ File System   │
            └──────────────┘
```

### 存储层说明

| 存储层 | 角色 | 说明 |
|--------|------|------|
| **IndexedDB（Dexie v12）** | 元数据存储 | 仅存元数据（Story/Character/VideoTask/Timeline/GeneratedFile 元数据），共 15 张表 |
| **FilesLocal（配置目录 FILES_DIR）** | 优先二进制存储 | 存储 Blob 二进制数据，通过 Vite 自定义插件 `filesStoragePlugin` 实现 |
| **OPFS（Origin Private File System）** | 降级二进制存储 | FilesLocal 不可用时的降级方案 |
| **OfflineCacheMigration** | 启动迁移 | 启动时迁移旧版 IndexedDB 中的二进制数据 |

### 15 张数据表

| 序号 | 表名 | 用途 |
|------|------|------|
| 1 | `storySpaces` | 故事空间 |
| 2 | `characters` | 角色 |
| 3 | `backgrounds` | 背景 |
| 4 | `stories` | 故事 |
| 5 | `segments` | 分镜片段 |
| 6 | `videoTasks` | 视频任务 |
| 7 | `pipelineTasks` | Pipeline 任务 |
| 8 | `finalCuts` | 成片 |
| 9 | `savedImages` | 已保存图像 |
| 10 | `savedVoices` | 已保存语音 |
| 11 | `savedPrompts` | 已保存提示词 |
| 12 | `savedVideos` | 已保存视频 |
| 13 | `snapshots` | 快照 |
| 14 | `timelines` | 时间线 |
| 15 | `generatedFiles` | 生成文件 |

## 13. 故事电影（一键端到端）

`StoryFilmService` 提供一键端到端的故事电影生成能力，从主题/文本直接生成最终成片：

### 编排流程

```
主题（theme）或 文本（storyText）
  │
  ▼
故事生成（Story）
  │
  ▼
Pipeline 全流程编排
  │
  ▼
最终成片（Final Film）
```

### 关键约束

| 约束项 | 说明 |
|--------|------|
| **互斥输入** | `storyText` 与 `theme` 互斥，二选一 |
| **风格注入** | `videoStyle` 作为风格后缀注入 `PipelineOptions` |

### StoryFilmPage 三步向导

## 15. 设计约束与规范

### 架构约束

| 约束 | 说明 |
|------|------|
| **无 Service Worker** | 避免 cache-first 与跨域媒体拦截 |
| **无文本截断** | UI 使用软限制模式（红色边框 + 计数器 + toast 警告），Adapter 传递原始文本 |
| **集中式文本限制** | `TEXT_LIMITS`（UI 跨平台最小值）与 `ADAPTER_TEXT_LIMITS`（平台硬限制）集中定义于 `textLimits.ts` |
| **接口日志** | 所有 API I/O 通过 `CompositeLogger` 记录 |
| **智能降级** | AI 分镜/breakdown 服务在不可用时自动降级为本地 Mock 实现 |

### 持久化降级策略

- 持久化失败时回退原始 URL/数据，**不抛错**以保证 UI 不中断
- 大资源优先落 OPFS，避免 data:URI 膨胀与外部 URL 过期

### 错误处理规范

| 层级 | 处理方式 |
|------|----------|
| **能力不支持** | 抛 `CapabilityNotSupportedError`（带 `platform` + `capability`） |
| **Adapter** | 平台错误码归一化为领域错误，带上下文 |
| **Service** | 业务校验失败用 `throw new Error('英文短句')`，日志 `logger.warn/error` + `ctx()` |
| **UI** | `<AsyncState error onRetry>` 统一展示；全局兜底 `GlobalErrorCapture` |

## 16. Context Provider 层级

应用的 Context Provider 采用严格的嵌套层级，从外到内依次为：

```
ErrorBoundary
  └─ ThemeProvider
       └─ PlatformProvider
            └─ BrowserRouter (basename="/ai-video-studio")
                 └─ SpaceProvider
                      └─ ToastProvider
                           └─ ConfirmProvider
                                └─ Suspense
                                     └─ Routes (18 lazy routes)
```

### 层级说明

| 层级 | 职责 |
|------|------|
| `ErrorBoundary` | 全局错误边界捕获 |
| `ThemeProvider` | 主题管理（支持主题选择器） |
| `PlatformProvider` | 平台激活与路由管理 |
| `BrowserRouter` | 路由管理，basename 为 `/ai-video-studio` |
| `SpaceProvider` | 当前故事空间上下文 |
| `ToastProvider` | 全局 Toast 通知 |
| `ConfirmProvider` | 全局确认对话框 |
| `Suspense` | 懒加载fallback |
| `Routes` | 18 条懒加载路由 |

## 17. 空间管理

### 概念

`StorySpace`（故事空间）是 AI Video Studio 的**顶层组织单元**。所有实体（角色、背景、故事等）均归属于一个 Space。

### 级联删除

`deleteSpace` 使用**事务**实现跨 15 张表的级联删除，确保数据一致性：

```
deleteSpace(spaceId)
  │
  ▼
  事务开始
  │
  ├─ 删除 storySpaces 记录
  ├─ 删除关联 characters
  ├─ 删除关联 backgrounds
  ├─ 删除关联 stories
  ├─ 删除关联 segments
  ├─ 删除关联 videoTasks
  ├─ 删除关联 pipelineTasks
  ├─ 删除关联 finalCuts
  ├─ 删除关联 savedImages
  ├─ 删除关联 savedVoices
  ├─ 删除关联 savedPrompts
  ├─ 删除关联 savedVideos
  ├─ 删除关联 snapshots
  ├─ 删除关联 timelines
  └─ 删除关联 generatedFiles
  │
  ▼
  事务提交
```

### 快照服务

`SnapshotService` 提供空间级快照管理：

| 规则 | 说明 |
|------|------|
| **快照上限** | 每个 Space 最多 50 个快照 |
| **自动快照** | 删除/重置操作前自动创建快照 |
