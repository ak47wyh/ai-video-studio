## 1. 项目架构总览

### 1.1 分层架构(六边形 / Ports & Adapters)

本项目采用六边形架构(又称端口与适配器架构),核心目标是**将业务逻辑与外部依赖隔离**,确保领域层零框架依赖、可独立测试。

```
┌─────────────────────────────────────────────────────────────────────┐
│                        UI 层 (React)                                 │
│   18 个页面 · 47+ 组件 · 22 个 Hook · 5+ Context                     │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ 依赖注入
                  dependencies.ts(DI 容器,装配所有依赖)
                               │
┌──────────────────────────────┴──────────────────────────────────────┐
│                    领域服务层 (Domain Services)                       │
│   27 个 Service · PlatformRouter 多平台路由                           │
├──────────────────────────────────────────────────────────────────────┤
│                    领域端口层 (Domain Ports)                          │
│   17 个 Port 文件 · 出站端口契约                                      │
│   (IVideoPort / IVoicePort / IImageGeneratorPort / ...)              │
├──────────────────────────────────────────────────────────────────────┤
│                    领域实体层 (Domain Entities)                       │
│   models.ts · platform.ts · errors/                                  │
└──────────────────────────────▲──────────────────────────────────────┘
                               │ 实现 Port 接口
┌──────────────────────────────┴──────────────────────────────────────┐
│                    适配器层 (Adapters)                                │
│   7 大平台(MiniMax/Volcengine/Kling/Wan/Hunyuan/Zhipu/Vidu)         │
│   + FFmpeg / Whisper / IndexedDB / OPFS 基础设施适配器                │
└─────────────────────────────────────────────────────────────────────┘
```

#### 依赖方向铁律

```
ui  ──->  domain  ←──  adapters
```

- `ui` 层依赖 `domain`(通过 Service / Port 接口)
- `adapters` 层依赖 `domain`(实现 Port 接口)
- **`domain` 永远不依赖外层**(不 import react / axios / i18next 等)

### 1.2 架构边界约束(ESLint 强制,违反即编译失败)

`src/domain/**` 目录内**禁止**以下导入,必须通过 Port 抽象:

| 禁止依赖                                  | 替代方案                          |
| ----------------------------------------- | --------------------------------- |
| `react` / `react-dom`                     | 通过 Port 抽象副作用              |
| `i18next` / `react-i18next`               | 通过 `ITranslationPort`           |
| `axios` / `fetch` 直调                    | 通过 `OutboundPorts`              |
| `@ffmpeg/*`                               | 通过 `IFFmpegPort`                |
| `dexie` / `dexie-react-hooks`             | 通过仓储 Port                     |
| `localStorage` / `sessionStorage` / `window.localStorage` | 通过 `ISnapshotRepository` 等 Port |
| `alert` / `confirm`                       | 通过 `IConfirmPort` / `INotificationPort` |

> Service 优先采用**构造函数注入 Port 接口**,而非 import 具体类。

### 1.5 TypeScript 规范

- **强制** `import type` 导入纯类型(`verbatimModuleSyntax: true`)
- `noUnusedLocals` / `noUnusedParameters` / `noFallthroughCasesInSwitch` 严格开启
- 不用 `enum` / namespace(`erasableSyntaxOnly: true`),用字面量联合类型
- 禁用 `any`,确需逃逸用 `unknown` + 收窄
- 优先 `interface` 描述形状,`type` 描述联合/工具类型
- Context 用独立 interface,字段尽量 optional;Result 用独立 interface

```ts
import type { IImageGeneratorPort, ImageGenerationContext } from '../ports/OutboundPorts';
import { PlatformRouter } from './PlatformRouter'; // 值导入分开
```

## 2. 领域层详解(Domain)

领域层是整个应用的核心,包含纯业务逻辑,零框架依赖。由 **Ports(端口契约)**、**Services(业务服务)**、**Entities(数据实体)**、**Errors(领域错误)**、**Constants/Data(常量与预设数据)** 五部分组成。

### 2.1 Ports(端口契约,17 个文件)

端口是领域层定义的**能力契约**,由适配器层实现。领域层只依赖接口,不依赖具体实现,从而实现依赖反转。

#### 2.1.5 Port 设计要点

- 相关能力聚合在同一文件(如 `OutboundPorts.ts` 聚合所有生成类端口)
- 接口前用中文 JSDoc 说明用途
- 平台能力差异通过 `XxxCapabilities` 接口声明;不支持的子能力由 Adapter 抛 `CapabilityNotSupportedError`,**禁止返回 `undefined`**
- 流式方法返回 `AbortController` 或 Handle 对象,支持取消

### 2.2 Services(业务服务,27 个)

#### 2.2.1 PipelineService.ts(最核心)

**职责**:编排短视频生成全流程流水线,从故事拆分到最终成片。

**依赖(16 项)**:

```
storyRepo · segmentRepo · characterRepo · backgroundRepo ·
videoTaskRepo · finalCutRepo · router · postProcess ·
subtitle · fileStorage · logger · eventBus · configStore ·
storyBreakdownPort · promptContextBuilder · bgmRecommendationService ·
musicService · pipelineTaskRepo · httpFetch
```

**9 个阶段及进度区间**:

```
splitting            (2%  - 5%  )   故事拆分为段落
generating_images    (10% - 20% )   为角色/场景生成参考图
generating_audio     (25% - 40% )   段落旁白语音合成
generating_bgm       (45% - 50% )   背景音乐生成
generating_videos    (55% - 80% )   各段落视频生成(最耗时)
post_processing      (82% - 90% )   视频后处理(音频混合+转场)
generating_srt       (91% - 92% )   字幕生成
burning_subtitles    (93% - 95% )   字幕烧录
complete             (100%      )   完成
```

**任务驱动 + 轮询兜底**:

- 订阅 `IEventBus` 的 `video.task.completed` / `video.task.failed` 事件
- 同时启动轮询:每 5 秒查询一次,最多 120 次(约 10 分钟)

**持久化策略**:

- 每次进度通知时调用 `persistTask()` 落盘
- 启动时调用 `restoreActiveTasks()` 加载运行中任务,将中间阶段任务标记为 `failed`(避免僵尸任务)

**assembleFinalVideo() 成片组装流程**:

```
下载所有段落视频
    ↓
音频混合(旁白 + BGM,BGM 音量 30%)
    ↓
mergeVideoAudio(视频 + 混合音频合并)
    ↓
淡入淡出转场(offset = 前一段时长 - 0.5s)
    ↓
烧录字幕
    ↓
提取缩略图
    ↓
最终成片
```

**公共 API**:

```ts
runFullPipeline(storyId, options)
createTask · startStage · markComplete · markFailed · cancelTask
subscribe · getTask · listTasks
assembleFinalVideo · restoreActiveTasks · destroy
```

#### 2.2.2 PlatformRouter.ts(多平台路由)

**设计模式**:注册表模式(Registry Pattern)

**数据结构**:

```
Map<PlatformCapability, Map<PlatformId, AdapterFactory>>
缓存:Map<PlatformCapability, CachedAdapter>
```

构造函数订阅 `configStore.onPlatformChange` -> 调用 `reset()` 清除所有缓存。

**平台能力注册矩阵(5 能力 × 7 平台 = 25 个适配器工厂)**:

| 能力    | minimax | volcengine | kling | wan | hunyuan | zhipu | vidu |
| ------- | :-----: | :--------: | :---: | :-: | :-----: | :---: | :--: |
| video   |    ✓    |     ✓      |   ✓   |  ✓  |    ✓    |   ✓   |  ✓   |
| image   |    ✓    |     ✓      |   ✓   |  ✓  |    ✓    |   ✓   |  ✓   |
| text    |    ✓    |     ✓      |   -   |  ✓  |    ✓    |   ✓   |  -   |
| voice   |    ✓    |     ✓      |   -   |  ✓  |    ✓    |   ✓   |  -   |
| music   |    ✓    |     -      |   -   |  -  |    -    |   -   |  -   |

**resolveAdapter 流程**:

```
读取 activePlatform
    ↓
查找注册表 registry[capability][platform]
    ↓
未注册 -> throw UnsupportedCapabilityError
    ↓
已注册 -> 返回缓存的适配器实例(无缓存则实例化并缓存)
```

**火山引擎双协议路由**:

- Video / Image:始终使用 OpenAI 协议
- Text:根据 `volcArkTextProtocol` 选择(OpenAI / Anthropic)
- Voice:使用原生 speech 端点

#### 2.2.4 Service 编写规范

- 构造函数注入所有依赖,字段声明为 `private`
- 类顶部 JSDoc 说明:职责、依赖项、关键设计决策(可标 Phase)
- 公共方法以业务动作命名(如 `generateCharacterImage`)
- 日志走 `ILoggerPort`,统一 `ctx()` 工厂附加 `service` 字段
- 业务校验失败 `throw new Error('英文短句')`,面向用户文案交 UI 层 i18n

```ts
private ctx(extra: LogContext = {}): LogContext {
  return { service: 'ImageGenerationService', ...extra };
}
```

### 2.4 Errors(领域错误,9 个类)

所有错误类继承抽象基类 `DomainError`,包含 `code: DomainErrorCode`。

**DomainErrorCode 联合类型**:

```ts
type DomainErrorCode =
  | 'UNSUPPORTED_CAPABILITY'
  | 'AUTH'
  | 'RATE_LIMIT'
  | 'NETWORK'
  | 'TIMEOUT'
  | 'QUOTA_EXHAUSTED'
  | 'VALIDATION'
  | 'ILLEGAL_STATE_TRANSITION'
  | 'UNKNOWN';
```

| 错误类                          | code                       | 触发场景                                       |
| ------------------------------- | -------------------------- | ---------------------------------------------- |
| `DomainError`(抽象基类)        | -                          | `code` · `context` · `cause` · `toJSON()`      |
| `AuthError`                     | `'AUTH'`                   | 401/403/Token 过期                             |
| `RateLimitError`                | `'RATE_LIMIT'`             | 429,context 含 `retryAfterSec`                 |
| `NetworkError`                  | `'NETWORK'`               | fetch TypeError / CORS / DNS                   |
| `TimeoutError`                  | `'TIMEOUT'`                | 轮询/任务超时                                  |
| `QuotaExhaustedError`           | `'QUOTA_EXHAUSTED'`        | 402 配额耗尽                                   |
| `ValidationError`               | `'VALIDATION'`            | context 含 `field`                             |
| `IllegalStateTransitionError`   | `'ILLEGAL_STATE_TRANSITION'` | 状态机违规                                   |
| `UnsupportedCapabilityError`    | `'UNSUPPORTED_CAPABILITY'` | 平台不支持该能力,自动推荐替代平台             |
| `VoiceSubCapabilityNotSupportedError` | `'UNSUPPORTED_CAPABILITY'` | 语音子能力不支持,别名 `CapabilityNotSupportedError` |

**错误处理分层策略**:

- **能力不支持**:抛 `CapabilityNotSupportedError`(带 `platform` + `capability`)
- **Adapter**:平台错误码归一化为领域错误,带上下文
- **Service**:业务校验失败用 `throw new Error('英文短句')`,日志 `logger.warn/error` + `ctx()`
- **持久化降级**:失败回退原始 URL/数据,不抛错以保证 UI 不中断
- **UI**:`<AsyncState error onRetry>` 统一展示;全局兜底 `GlobalErrorCapture`

## 6. 火山引擎 Agent Plan 接入规则

> 本项目仅接入 Agent Plan 套餐,不使用普通方舟后付费。官方文档:https://www.volcengine.com/docs/82379/2366394

### 6.1 套餐与路径前缀

火山方舟存在两套接入体系,API Key 类型与路径前缀**必须配对,交叉使用即 404**:

| 接入体系                | 路径前缀        | 本项目      |
| ----------------------- | --------------- | ----------- |
| 普通方舟(后付费)      | `/api/v3`       | 不使用      |
| **Agent Plan(套餐订阅)** | **`/api/plan/v3`** | **唯一使用** |

### 6.2 代理配置规则

- **仅火山引擎平台**所有接口(Ark OpenAI / Ark Anthropic / Speech HTTP / Speech WebSocket)必须走 Vite dev server proxy,不允许直连
- 代理路径前缀**仅限三个**:`/volcengine-ark` / `/volcengine-speech` / `/volcengine-speech-ws`,禁止新增其他火山前缀
- 火山引擎 Base URL 默认值统一为代理前缀(`/volcengine-*`),**禁止区分 DEV/PROD**(禁止 `import.meta.env.DEV ? ... : 'https://...'` 写法)
- `/volcengine-ark` 代理必须使用**智能 rewrite 按请求路径分流**:
  - `/images/*`、`/contents/*` -> `/api/plan/v3`(Agent Plan,图片/视频生成)
  - 其他路径(`/audio/*`、`/chat/*`) -> `/api/v3`(普通方舟,语音合成/文本对话)
- Vite dev server 必须 `strictPort: true`,端口冲突直接报错
- WebSocket 代理需显式 `ws: true`
- 禁止使用 Cloudflare Worker / nginx / 其他自建反代方案
- 遇到配置异常优先用 `npm run dev:clean` 清除缓存重启
- 其他平台(MiniMax 原生 / Coze / Kling / Wan / Hunyuan / Zhipu / Vidu 等)保持直连,不使用代理
- Vite proxy 配置位于 `vite.config.ts`,新增火山端点需同步更新代理规则

### 6.3 Agent Plan 支持的模型(图片生成)

官方文档 82379/2366394 明确 Agent Plan **仅支持 `doubao-seedream-5.0-lite`** 一个图片模型。不在列表中的模型(如 `doubao-seedream-5-0-pro-260628`)会返回 404 "model does not support agent plan feature"。

**配置要求**:

- `src/domain/services/platformCapabilities.ts` 图片模型列表**仅保留 `doubao-seedream-5.0-lite`**,标记 `recommended: true`,删除所有非 Agent Plan 模型(5.0 Pro / 4.5 / 4.0 / 3.0 t2i / Seededit 3.0)
- `src/adapters/outbound/config/ApiConfigStore.ts` 默认 `volcArkImageModel: 'doubao-seedream-5.0-lite'`
- **铁律**:仅改默认值不够,必须确认 `useImageModels` 的 `fallbackModelId`(优先选 `recommended: true`)能选到 5.0 Lite

### 6.4 Base URL 统一

`ApiConfigStore.ts` 中三个 Base URL 字段统一为 `/volcengine-ark`:

```ts
volcArkBaseUrl: '/volcengine-ark',
volcArkAgentPlanBaseUrl: '/volcengine-ark',
volcArkAnthropicBaseUrl: '/volcengine-ark',
```

### 6.5 HttpClient 工厂方法

- 图片适配器(`VolcengineImageAdapter`)和视频适配器(`VolcengineVideoAdapter`)必须用 `VolcengineHttpClient.createAgentPlan(config)` 工厂方法
- Base URL 与普通方舟相同(统一走 `/volcengine-ark` 代理),由 Vite proxy 智能 rewrite 分流

### 6.6 Service 层模型 ID 透传(关键)

**铁律:Service 层必须透传 UI 层传入的 `context.model`,禁止丢弃重建。**

`ImageGenerationService.generateImage` 必须用解构透传全部字段:

```ts
const { character, background, ...rest } = context;
const ctx: ImageGenerationContext = { ...rest, ... };
```

**禁止**只取部分字段(曾导致 `context.model` 被丢弃,Adapter 回退到 `config.volcArkImageModel`,触发 404)。

### 6.7 模型解析顺序

Adapter `resolveModel` 解析顺序(三层都应指向 `doubao-seedream-5.0-lite`):

```
1. context.model                    (优先,UI 层传入)
    ↓ 未提供则
2. config.volcArkImageModel         (配置默认值)
    ↓ 未提供则
3. 注册表默认值 getDefaultImageModel()
```

### 6.8 404 排查要点

1. **404 Not Found(路径错误)**:确认 `vite.config.ts` 只有 `/volcengine-ark` 代理;确认 dev server 已重启;curl 测试期望 401(非 404)
2. **404 "model does not support agent plan feature"**:确认注册表无残留非 Agent Plan 模型;确认 `recommended: true` 在 5.0 Lite 上;确认 Service 层透传了 `context.model`;浏览器 DevTools 拦截请求确认 body 中 `model` 为 `doubao-seedream-5.0-lite`
3. **端口冲突导致旧配置生效**:`lsof -i :5173` 查看占用进程;`strictPort: true` 已强制报错

详细接入规则与修复记录见 `docs/VolcengineAgentPlanIntegrationRules.md` 和 `docs/ImageGeneration_404_Fix_Operation_Log.md`。

### 7.3 Mock 适配器使用范围检查

- Mock 适配器(`Mock*.ts`)**仅用于测试场景**(`*.test.ts` / `src/test/__tests__/`)
- 生产/开发运行时**强制使用真实适配器**,API Key 缺失时由 Adapter 抛 `CapabilityNotSupportedError`
- `dependencies.ts` 装配 Mock 时必须增加守卫:`if (import.meta.env.MODE === 'test' || import.meta.env.VITEST)`
- 测试场景可显式构造 Mock 实例注入到 Service,不通过全局装配
- 禁止以"无 API Key 时静默降级到 Mock"为由在生产/开发运行时启用 Mock
